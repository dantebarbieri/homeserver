# CLAUDE.md

This file provides guidance to Claude Code when working with the `nixos/` directory.

## Key Files

- `flake.nix` / `flake.lock` — Entry point. Pins nixpkgs (`nixos-unstable`), Home Manager and `nix-index-database`; outputs `nixosConfigurations.homeserver`. CI (`.github/workflows/nixos-flake-update.yml`) bumps the lock daily; never hand-edit it.
- `configuration.nix` — Root module: imports `hardware-configuration.nix` and every `modules/*.nix`, and holds `system.stateVersion`.
- `modules/*.nix` — One concern per file: `base` (boot, Nix, locale, sudo-rs), `networking` (bond, networkd, firewall), `storage` (RAID/LVM/SMART), `users`, `shell` (zsh, packages, system git), `home-manager`, `compat`, `ssh`, `forgejo-runner`, `docker` (daemon + compose updater), `mirklurk`, `auto-upgrade`, `reboot-reminder`, `ntfy`, `backups`, `nvidia`.
- `lib/shared.nix` — Values used by several modules (`ntfyUrl`, `ntfyTopic`, `ntfyNotify`, `smartdAlert`, `mdadmAlert`, `mirklurkDeploymentCondition`). Import with `inherit (import ../lib/shared.nix { inherit config pkgs; }) …;`.
- `home/danteb.nix` — Home Manager config for `danteb` (zsh + Zim, `~/.zimrc`, git identity and SSH signing). **Public and copied to the world-readable Nix store: never put secrets here**; they belong in the untracked `~/.zprofile.local` / `~/.zshrc.local`.
- `hardware-configuration.nix` — **Auto-generated by `nixos-generate-config`. Do not edit manually.**
- `nix-functions.zsh` — Nix convenience shell functions (`nsp`, `nss`, `nwp`), sourced by `interactiveShellInit` in `modules/shell.nix`. `nwp` queries `nix-locate`, which uses the prebuilt `nix-index-database` pinned in the lock; no index is built on the server.
- `docker-functions.zsh` — Docker Compose convenience shell functions (`dci`, `dce`, `dcs`, `dcl`, `dcr`, `dcu`, `dcupdate`), sourced by `interactiveShellInit` in `modules/shell.nix`
- `tests/test_health_cleanup.py` — Evaluates the flake and mock-runs unit scripts; run in CI by `nixos-validate.yml`.

`/etc/nixos` on the server is a symlink to this directory, so `nixos-rebuild` auto-detects `flake.nix` and builds `#homeserver`.

The flake is evaluated as `git+file`, so Nix sees only **tracked** files: `git add` a new module before evaluating or rebuilding, and untracked secrets (e.g. `docker/.env`) never reach the store. Uncommitted edits to tracked files anywhere in the repo *are* copied by a manual rebuild; the nightly `nixos-upgrade` uses `ref=main` and only sees commits. Never evaluate it as a `path:` flake.

## Where things go

- New system service, timer or package → the matching `modules/*.nix` (or a new module added to `imports` in `configuration.nix`).
- Personal dotfiles, shell behavior or per-user tools for `danteb` → `home/danteb.nix`. Machine-wide shell setup (aliases, functions, fastfetch) stays in `modules/shell.nix`.
- A value needed by more than one module → `lib/shared.nix`.
- Options the tests assert on → keep `tests/test_health_cleanup.py` in sync.

## Common Patterns

### Systemd service + timer pair

```nix
systemd.services.my-service = {
  description = "...";
  after = [ "network-online.target" ];
  wants = [ "network-online.target" ];
  path = with pkgs; [ curl bash ];      # executables available in script
  serviceConfig = { Type = "oneshot"; };
  script = ''
    # shell script body
  '';
};

systemd.timers.my-service = {
  wantedBy = [ "timers.target" ];
  timerConfig = {
    OnCalendar = "*-*-* 04:00:00";
    Persistent = true;                   # run missed timers on boot
  };
};
```

### ntfy alerting

All monitoring scripts send alerts via curl to `${ntfyUrl}/${ntfyTopic}`:

```nix
${pkgs.curl}/bin/curl -s \
  -H "Title: ALERT on ${config.networking.hostName}" \
  -H "Priority: high" \
  -H "Tags: warning,computer" \
  -d "message body" \
  "${ntfyUrl}/${ntfyTopic}"
```

Priority levels: `urgent` (RAID failure), `high` (SMART warnings), `default`, `low` (info).

### Activation scripts

One-time setup tasks (e.g., deploy key generation):

```nix
system.activationScripts.name = lib.stringAfter [ "users" ] ''
  # runs on nixos-rebuild switch
'';
```

## Active Timers

| Timer | Schedule | Purpose |
|-------|----------|---------|
| `docker-compose-update` | Daily 04:00 (±5m) | Pull monorepo, update containers (never the `mirklurk-release` wiki frontend) |
| `mirklurk-auto-update` | Daily 04:15, after the updater | Build/deploy eligible MediaWiki 1.43 base updates of the wiki; ntfy only on failure or stall |
| `mirklurk-sitemap` | Daily 05:30 | Guarded native sitemap refresh + public freshness checks |
| `mirklurk-snapshot` | Daily 03:15 | SQL + images/branding snapshot; briefly stops only the wiki |
| `mirklurk-backup-check` | Hourly :45 | SQL/files backup freshness + free space/inodes -> ntfy |
| `drive-health-check` | Every 6 hours | RAID + LVM health → ntfy |
| `mdadm-scrub` | Weekly Sunday 02:00 | RAID parity scrub |
| `nixos-upgrade` | Daily 04:30 | `nixos-rebuild boot` of the committed `flake.lock` (no lock update on the server) |
| `reboot-reminder` | Daily 10:00 (±10m) | ntfy when a staged kernel/driver/OS update isn't running and uptime is ≥ 7 days; held while `md0` is scrubbing or rebuilding |

The root-owned `/var/lib/mirklurk-upload-deployment/hold` file gates both the
service and timer for Docker updates, OS upgrades, offsite sync, wiki snapshots,
wiki backup checks and wiki auto-updates. It survives a planned reboot without stopping the
existing SQL backup sidecar. It is world-readable so non-root agents can check
for it without `sudo`. See `docker/docs/MIRKLURK-UPLOADS.md` before creating
or removing it; never clear another operator's hold or resume timers before
coordinated deployment acceptance.

Terminal mail/calendar packages, the login calendar, and `vdirsyncer-sync` were
retired in September 2026. Preserve existing user data and credentials; do not
reintroduce the timer just because optional `mail-config/` templates remain.

## Networking & IPv6

- **Bond**: `bond0` (active-backup, mode 1) bonding `enp66s0f0` + `enp66s0f1` with `enp66s0f1` as primary. The ASUS GT-BE98 Pro does not support LACP on its 2.5G LAN ports, so active-backup provides fault tolerance only (no aggregated throughput). The bond's MAC is pinned to `enp66s0f1`'s MAC (`9c:6b:00:45:2b:c2`) so the IPv6 EUI-64 address stays stable across reboots and failovers — without this, the bond gets a random MAC and the AAAA record / router firewall rules break.
- **IPv4**: Static `192.168.50.100/24` on `bond0`, gateway `192.168.50.1`
- **IPv6**: Received via SLAAC from ASUS GT-BE98 Pro router (Spectrum ISP, `2603:8080:1e00:1c97::/64` prefix). `tempAddress = "disabled"` ensures a stable EUI-64 address for the AAAA DNS record. The resulting GUA is `2603:8080:1e00:1c97:9e6b:ff:fe45:2bc2`.
- **Firewall**: NixOS firewall is enabled by default and blocks all inbound except SSH. `networking.firewall.allowedTCPPorts` / `allowedUDPPorts` must explicitly list every port that needs inbound access (80, 443, game ports, Coturn, Plex, LiveKit, etc.). Port 28 (SSH) is auto-opened by `services.openssh`.
- **Router IPv6 firewall**: The ASUS router also has an IPv6 firewall (separate from IPv4 port forwarding). Inbound IPv6 rules must be added in the router admin under **Firewall > IPv6 Firewall** for each service port, specifying the server's GUA as Local IP.

## Important Caveats

- Use full Nix store paths in scripts: `${pkgs.curl}/bin/curl`, not just `curl` (unless added to `path`)
- Services don't inherit shell aliases/functions — use `path` and `environment` explicitly
- The docker-compose-update service uses `git -c safe.directory=/srv/homeserver` because the repo is owned by `danteb` but the service runs as root. `nixos-upgrade` evaluates the same repo as root through libgit2, which ignores `-c`, so `modules/shell.nix` also sets `safe.directory` in the system git config — keep both.
- nixpkgs splices `system.autoUpgrade.flake` and `flags` into the upgrade script **unquoted**, so the flake URL (which contains `&`) goes through `lib.escapeShellArg`. The test tokenizes the script like bash to catch regressions.
- `sudo-rs` replaces classic sudo — the Rust implementation
- When adding a new externally-exposed port, update **three places**: (1) `networking.firewall` in `modules/networking.nix`, (2) router IPv4 port forwarding, (3) router IPv6 firewall inbound rules
- `zimfw upgrade` does not work: zimfw comes from nixpkgs and updates with the flake lock.

## Commands

```bash
sudo nixos-rebuild switch    # Apply changes (git add new files first)
sudo nixos-rebuild boot      # Stage for next boot (driver/kernel changes)
sudo nixos-rebuild test      # Test without persisting
python3 nixos/tests/test_health_cleanup.py    # From repo root; evaluates the flake
```
